# 车卡规范

> 这份文档是**引擎实际执行的规则**，不是建议。
> AI 车出来的卡要先过这里，过不了就回炉；回炉还不行，由引擎按确定性算法裁到合法。
> **进入跑团的卡一定是合法的**——不存在"警告一下但照样开跑"。

为什么单独立一份：车卡是整个引擎里**唯一一处让 AI 自己算数字**的地方。
属性是引擎掷的、骰子是引擎掷的、伤害是引擎算的，只有技能点分配交给了 AI。
而模型算加法非常不可靠——它会给自己多分几十点，会把技能顶到 95%，
而且它自己不觉得有问题。所以这块必须由代码兜住。

代码位置：`engine/chargen.py`。改规则改这里 + 改本文档，两处必须一致。

## 0. 权威源是**用户那张角色卡**

不是引擎里另写一张表——是 `data\templates\COC7空白卡.xlsx` 本身。这张卡就是个计算器：

| 卡上的位置 | 内容 | 引擎怎么用 |
|---|---|---|
| `职业列表` D 列 | 信用评级区间（`30-70`） | 直接读，用来夹 CR |
| `职业列表` E 列 | 职业属性（`教育×2＋敏捷×2`） | 给 AI 和日志看的说法 |
| `职业列表` F 列 | 点数公式（`=EDU*2+MAX(DEX*2,APP*2)`） | 求值算职业点 |
| `本职技能` 矩阵 | ★/☆/☯/⊙/※ 标出的本职技能 | 判断哪些技能能吃职业点 |
| `人物卡` N/P 列 | 技能表把点数分成**职业列 + 兴趣列** | 引擎按两本账写进去 |
| `人物卡!J50` | 自己算出「剩余职业点=X 剩余兴趣点=Y」 | 写完能对得上，用户一眼能核 |

`engine/cardcalc.py` 负责读它。**卡读不到才退回引擎内置的那张表**——
内置表一开始就猜错了好几处（记者其实是「教育×2＋外貌或敏捷×2」，
本职技能里有闪避、恐吓、取悦、说服、估价）。既然用户手里有权威数据，
引擎就不该自己编一套。

读卡上那个 F 列公式时只按白名单求值（属性名 + `MAX/MIN/SUM/INT/ROUND`），
形如 `=__import__("os").system(...)` 的一律拒绝。

## 1. 点数从哪来

一个人有两笔技能点，**分开记账**：

| 账 | 公式 | 能花在哪 | 卡上写在哪一列 |
|---|---|---|---|
| 职业技能点 | 卡上 `职业列表!F` 那一列 | **只能**花在这个职业的本职技能上 | `N`（职业） |
| 兴趣技能点 | `INT×2` | 任何技能都行 | `P`（兴趣） |

- 两笔不能互相挪用。拿兴趣点去点本职技能可以，拿职业点去点本职之外的技能**不行**。
- 分配顺序是固定的：**本职技能先用职业点付**（信用评级和母语排最前），
  职业点掏空了剩下的走兴趣点；非本职技能只能用兴趣点。
- 点数**不必花完**，但绝不能超。"还剩 30 点没用"不是违规，
  卡上会显示成「剩余职业点/剩余兴趣点」，日志里也会提一句。
- 信用评级的点数**也从职业点里出**（它的基础值是 0，所以 CR 40 就是花 40 点）。
  这也是为什么分配时它排在第一个吃职业点。

### 引擎查得动什么、查不动什么

这点必须说清楚，免得规范写得比实现硬：

| 规则 | 引擎能不能查 | 怎么查 |
|---|---|---|
| 合计不超预算 | ✅ 能 | `最终值 − 基础值` 逐项加总 |
| 单项 ≤ 90 / 不低于基础值 | ✅ 能 | 逐项比 |
| 克苏鲁神话 = 0 | ✅ 能 | 逐项比 |
| 信用评级在职业区间内 | ✅ 能 | 读卡上的 `职业列表!D` |
| **非本职技能的点数 ≤ 兴趣点** | ✅ 能 | 花在本职之外的点数**只可能**来自兴趣点 |
| 职业点是否真的只花在本职技能上 | ❌ **查不动** | 见下 |

最后一条为什么查不动：卡上写的是**最终值**，而兴趣点本来就可以点本职技能。
所以「本职技能花掉多少」是**推不出来**的——同一个最终值，
既可能是"职业点 + 一点兴趣点"，也可能是"兴趣点 + 一点职业点"。
要查必须让 AI 额外申报每一个点的来源，代价大、还容易解析失败，
而它带来的实际约束**已经被上一条覆盖**：想拿职业点去点本职之外的技能，
那笔点数就落在"非本职"那一栏里，超了兴趣点就会被抓。
所以引擎只查上一条，这一条靠提示词和自觉。

不过**写卡的时候**引擎是知道来源的——分配表（`allocate()` 的 `rows`）
把每一项拆成 `base / occ / interest` 三段写进那两列，
所以卡自己的计算器能算平，用户打开卡看到的就是同一套数字。

## 2. 卡上写的是总值，不是投入

技能表里写的是**最终值**（基础值 + 投入的点）：

```
侦查: 65      ← 侦查基础值 25，也就是说往里投了 40 点
```

所以「花掉了多少」一律由引擎反推：`max(0, 最终值 - 该项基础值)`。

基础值有三项是**算出来的**，不是常量，写错了整套数字就全错：

| 技能 | 基础值 |
|---|---|
| 母语 | `EDU` |
| 闪避 | `DEX ÷ 2`（向下取整） |
| 克苏鲁神话 | `0` |

其余见 `engine/rules.py` 的 `RULES_SKILL_BASE`；没列出的技能基础值按 `1`。

## 3. 四条铁律

违反任意一条，这张卡就是不合法的。

1. **单项上限 90。** 车卡阶段任何技能最终值不得超过 90
   （`SKILL_CAP`）。想上 90 以上得等跑团中靠成长检定慢慢涨。
2. **不得低于基础值。** 侦查基础 25，写 `侦查: 20` 是错的——
   基础值不是"可以不要"的东西。低于基础值会被抬回基础值。
3. **克苏鲁神话必须是 0。** 车卡阶段不允许分配神话技能。
   这是游戏内设定：调查员开局还没疯到那个地步。
4. **信用评级必须是职业允许的区间内。** 例如医生 30–80、记者 9–30。
   它的点数从**职业技能点**里出（基础值是 0，所以 CR 40 就是花 40 点）。

## 4. 违规了怎么办

分三步，从轻到重：

**第一步：回炉。** 引擎把违规清单**原样**交回给 AI，连同它自己刚写的那张卡，
让它重车一次。清单是具体的，不是"你的卡有问题"：

```
你这张卡有几处不合规，重车一遍：
· 「射击」85% —— 超出上限 90？不，是「闪避」写了 12，低于它的基础值 35（DEX 70÷2）
· 兴趣技能点超支：本职技能之外的技能花掉 150 点，兴趣点只有 120 点
· 信用评级 5 不在警官的 20–50 区间内
重车时只改这些地方，其余保持你想玩的样子。
```

**第二步：引擎裁剪。** 回炉只给一次机会（省钱，也避免无限循环）。
不管 AI 第二次写成什么样，引擎都会做一遍**确定性修正**，顺序固定：

1. 克苏鲁神话清零
2. 低于基础值的抬到基础值
3. 高于 90 的压到 90
4. 信用评级夹进职业区间（缺了就补区间的下限）
5. 还算出来超支就先削「非本职技能」那一栏（超了兴趣点），
   再按总账削；从**投得最多**的技能开始，削到刚好用完预算为止，
   且任何一项都不低于它的基础值
6. 削完再核一遍，最多重复 3 轮（防止 CR 单独就把预算吃光这类怪情况）
7. 全程按技能名排序做稳定处理，同样的输入一定得到同样的输出

**信用评级不参与削减**——它是职业身份，削了等于把人设削坏。
所以极端情况下可能出现"CR 就占掉大半职业点"，那时被削的是别的技能。

每一步都写进日志，用户看得到：

```
〔修正〕「闪避」12 → 35（不得低于基础值）
〔修正〕「射击」95 → 90（超过 90 上限）
〔修正〕兴趣点超支 30 点，从「图书馆利用」削 30 → 50
```

**第三步：记档。** 修正前的问题、修正动作都写进座位状态
（`chargen_violations` / `chargen_repairs`），散场复盘和界面都能查到。
如果某个 AI 反复车出超支的卡，这里看得见——那是模型的问题，不是随机。

## 5. 属性那一边（顺带记一下）

属性的处置和技能不同：**属性完全不由 AI 决定**。

- 掷骰车卡：引擎 `roll_attributes()`，3d6×5 / (2d6+6)×5，LUCK 单独 3d6×5
- 购点车卡：AI 提方案，但引擎逐项校验（每项 40–90、八项合计 480），
  不合规就 `_fix_pointbuy()` 按预算拉回来
- 年龄补正：由引擎按规则书那张表扣 STR/CON/DEX 与 APP、并按次数掷 EDU 增强

AI 能碰的只有：**职业、技能点怎么分、带什么东西、背景故事、角色叫什么**。
职业和背景那部分属于角色扮演，引擎不干涉；数字那部分全部由引擎把关。

## 6. 名字

**引擎不预设角色名。** 以前 `make_pl_seat()` 会塞一张现成的调查员卡进去，
于是桌上从第一秒显示的就是引擎随手挑的名字，提示词里还会写
「守秘人给你预留的名字是「X」」——那个 X 跟守秘人毫无关系，纯粹是编的。

现在座位出厂时 `character` 是空的：

- 车卡之前，桌上坐的是**玩家本人**，显示的就是网名（`摇人`）
- 车卡时提示词明确说「名字由你取，没人会替你定」
- 角色一落地，显示立刻变成 `角色名（网名）`（`薇拉·布莱克（摇人）`）
- 但提示词和叙述里用的仍然是**角色名**——守秘人喊的必须是角色

## 7. 自检覆盖

`tools/selftest_offline.py` 的「车卡规范」一节会验证：

- 从卡里读到了职业表（>100 个职业）、记者的区间与公式取自卡本身、
  本职技能取自卡上的矩阵、可疑公式被拒
- 预算优先用卡里的算法；卡里没有的职业退回内置表；两边都没有退回 EDU×4
- 掷骰车卡的属性都是 5 的倍数、LUCK 是 3d6×5 单独掷的
- 购点方案超范围 / 超预算会被抓出来，并能自动拉回合计 480
- 年龄补正按表扣点
- **构造一张超支 + 超 90 + 低于基础值 + CR 越界的卡，验证：**
  违规全部被抓到（不是漏报）、修完之后合计不超预算、
  没有任何技能 > 90 或 < 基础值、克苏鲁神话为 0、CR 落在区间内、
  非本职技能的点数不超兴趣点
- 修正算法是确定性的：同一张烂卡跑两次得到同一个结果
- 离线模型车 60 张卡，一张违规的都没有
- 名字：座位出厂不带角色名、车卡前叫网名、车完立刻变「角色名（网名）」、
  但提示词里用的是角色名
