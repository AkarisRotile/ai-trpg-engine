# 写一个插件

插件是 `data/plugins/<id>/` 里的一个文件夹。放进去，重启界面，就能在
顶栏的 **🧩 插件** 里看到它。

`data/` 在 exe 同级，升级程序不会动它。所以插件不用重新打包。

---

## 最小的一份

```
data/plugins/我的插件/
  plugin.json
  page.html      可选
  ui.js          可选
```

`plugin.json`：

```json
{
  "name": "我的插件",
  "version": "0.1",
  "author": "你",
  "description": "一句话说清它是干什么的",
  "surface": "window",
  "entry": { "page": "page.html", "script": "ui.js" }
}
```

字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 显示名。不写就用文件夹名 |
| `version` | 否 | 随便写，只是显示 |
| `author` | 否 | 同上 |
| `description` | 否 | 插件管理页里显示 |
| `surface` | 否 | 见下表。默认 `modal` |
| `entry.page` | 否 | 插件页面的 HTML 片段，不是完整网页，不要写 `<html>` |
| `entry.script` | 否 | 页面逻辑。可以不要，那就只显示静态 HTML |
| `capability` | 否 | 占一个"坑位"，见下文 |
| `engine_options` | 否 | 插件要求引擎打开的选项，开关插件时自动设上/撤下 |

`entry` 里的路径只能指向插件自己的目录，写 `..` 会被拒绝。

---

## 三种"面"

| surface | 长什么样 | 适合 |
|---|---|---|
| `modal` | 整屏弹窗，和「模组」那一页同一个样子 | 有完整界面的大功能 |
| `window` | 可拖动的悬浮窗，能同时开好几个 | 边跑边看的调试面板、计数器 |
| `panel` | 右栏多一个标签页 | 轻量信息展示 |

`window` 的面会自动带一个标题栏，拖着标题栏就能挪。

## 能拿到什么

`ui.js` 会被当成一个函数体执行，你拿到一个参数 `DSH`：

```js
(function () {
  'use strict';

  DSH.id        // 你的插件 id
  DSH.root      // 插件目录的路径
  DSH.node      // 你的外壳节点（window 面就是那个悬浮窗）
  DSH.body      // 装 page.html 内容的容器，往这里放东西
  DSH.el(tag, className, text)   // 造节点，和界面内部用的一样
  DSH.esc(x)                     // 转字符串
  DSH.toast(msg, kind)           // 弹一条提示，kind 可以给 'ok' / 'err'
  DSH.call(方法名, ...参数)       // 调引擎。下面是常用的
  DSH.on(事件类型, 回调)          // 订阅引擎事件
  DSH.onEvent(回调)               // 订阅全部事件
  DSH.debug(...)                 // 打到控制台，会带上你的插件 id
})();
```

`page.html` 不要写 `<script>`，逻辑都放 `ui.js`。用 `DSH.body.querySelector()` 取元素。

## 能调的引擎方法

`DSH.call()` 后面接界面自己用的那些方法名。常用的：

| 方法 | 拿回来什么 |
|---|---|
| `state()` | 当前这一局的全部状态：座位、角色、属性、技能、场景、时间 |
| `bootstrap()` | 启动那一份：配置、模组清单、名册、术语表 |
| `poll_events()` | 自上次以来发生的事件。**你自己调会跟主循环抢**，尽量用 `DSH.on` |
| `seat_memory(座位id)` | 某个座位的记忆树 |
| `dice_log()` | 骰子记录，含每一颗骰子的原始点数 |
| `module_detail(模组id)` | 一个模组的详情 |
| `list_plugins()` | 插件清单 |
| `player_card(玩家id)` | 某个玩家的跨周目卡 |

界面能调的东西不止这些，`engine/app.py` 里所有不以 `_` 开头的方法都通。
不过那是内部接口，升级时可能变；依赖它们的话自己留个心眼。

想加新方法，改 `engine/app.py`，然后在这个表格里补一行。

## 能订阅的事件

事件长这样：

```js
{ type: 'narr', text: '……', name: '守秘人', seat_id: 'kp', meta: {...} }
```

`type` 常见的有：

| type | 什么时候来 | 里面有什么 |
|---|---|---|
| `narr` | 守秘人叙述 | 正文 |
| `act` | 某个角色的动作 | 正文、`seat_id` |
| `ooc` | 桌边的话 | 正文、`seat_id` |
| `think` | 角色的内心 | 正文 |
| `secret` | 守秘人的幕后状态 | 正文 |
| `dice` | 掷了骰子 | `meta` 里有原始点数、成功等级 |
| `system` | 引擎自己的动静 | 比如场景切换、守秘人拨钟 |
| `scene` | 换幕 | |
| `chargen` | 车卡过程 | |
| `debug` | 模型正在写什么 | 见下文。**只有开了调试旁路才有** |

`debug` 是旁路事件，不进主流水，只发给插件。一条长这样：

```js
{ type: 'debug', text: '正在写的那部分', meta: {
    seat: '咸鱼', phase: 'play', final: false } }
```

`final: true` 的那条是这一轮的完整结果，`meta` 里还带 `cleaned`（引擎清洗后的文字）、
`changed`（是否被改过）、`prompt_tokens` / `completion_tokens` / `latency_ms`。
想看完整的思维链，就订阅这个。

## 坑位（capability）

同一件事可以有好几个插件做，比如"看思维链"。这时候谁说了算？
给插件声明一个坑位，用户在插件管理页里挑一个当值。

```json
{ "capability": "thinking" }
```

目前认得的坑位：

| 坑位 | 是干什么的 | 官方那个 |
|---|---|---|
| `thinking` | 看模型的思维链和引擎改了什么 | `thinking-viewer` |

做了替代品，在 `plugin.json` 里写上同一个 `capability`，装进去，
在插件管理页把它选成当值就行，原来的那个会自动让位。

想让引擎打开调试旁路（不然收不到 `debug` 事件），写：

```json
"engine_options": { "debug_stream": true }
```

---

## 出错会怎么样

插件的脚本会被包起来跑。语法错了、初始化抛异常，都只会让**这个插件**
在管理页标红，界面其他地方不受影响。关掉它就好了。

插件里的事件回调也是各自包起来的，一个回调抛异常不影响别的插件。

**插件不做沙箱。** 它跑在同一个页面里，能碰 DOM，也能调引擎。
它是你自己装的代码，所以别装来路不明的。
