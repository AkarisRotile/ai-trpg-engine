# AI 跑团引擎 · COC 第七版

KP 和 PL **全部由 AI 担任**的《克苏鲁的呼唤》跑团引擎。
每个 AI 座位独立配 API Key，可视化界面由 exe 启动，跑团过程全自动。

---

## 快速开始

1. 双击 `dist\COC跑团引擎\COC跑团引擎.exe`
2. 右上角 **⚙️ 设置**：给每个座位配接口
   - **DeepSeek 官方**：接口选它，粘上 Key 就行
   - **自定义**：填任意 OpenAI 兼容端点的 Base URL / Key / 模型名
   - **离线模拟**：不联网不花钱，会完整走完车卡→审卡→掷骰→记忆→桌边对话的全流程
   - 有「一键填入 DeepSeek 官方地址」和「测试全部连接」
3. 点左上角大的 **🎬 开新团**（就在左栏最上面，不用翻菜单）
4. 依次点 **① 车卡 → ② 开局 → ▶ 自动推进**

> 每个座位是**独立**的：不同 AI 可以走不同服务商、用不同 Key。
> 可以给玩家用便宜快的模型，给守秘人用好一点的。

## 从源码一键构建

克隆下来之后，**一条命令**就能得到 exe：

```powershell
git clone https://github.com/AkarisRotile/ai-trpg-engine.git
cd ai-trpg-engine
powershell -ExecutionPolicy Bypass -File build.ps1
```

或者直接**双击 `build.bat`**（效果一样，出错会停住让你看信息）。

脚本会依次做六件事：

1. 找一个 Python 3.10+（`py -3` 或 `python` 都行）
2. 建一个干净的虚拟环境 `.venv`
3. 装 `requirements.txt` 里的依赖
4. **跑一遍离线自检**——引擎有问题会在这里就拦下来，不会打个坏包给你
5. 画图标（d20，纯几何算出来的，不是图片素材）
6. PyInstaller 打包 → **`COC跑团引擎.exe`（直接装到项目根目录，双击就能找到）**
   - 同目录会有一个 `_internal\`，那是程序自己的 DLL 和插件，**别删也别动**
   - 加 `--portable` 可以让成品留在 `dist\` 下，方便整个文件夹压缩分享

想跳过自检：`build.ps1 -SkipTests`；想从头重来：`build.ps1 -Clean`。

> 首次构建要下 PyMuPDF（约 20 MB），慢一点是正常的。
> 打完约 **81 MB**（exe 7.7 MB + `_internal` 73 MB），
> 因为里面带了 PDF 渲染（扫描件 OCR）和 Excel 读写（角色卡）。

## 开新团

左上角的 **🎬 开新团** 是主入口，三步一屏：

1. **跑什么** —— 选模组，或者选「自由跑团」现场编。
   旁边有 **📂 打开模组仓库**，下载来的剧本直接粘进去
2. **谁坐哪儿** —— 守秘人下拉 + 玩家勾选，或者直接点 **🔄 换庄** 轮到下一位

上一局会自动存档，随时能在「💾 存档」里接回来。

## 车卡：一段过程，不是一个动作

车卡在这里是一整段桌上互动，顺序是：

| 步 | 谁 | 干什么 |
|---|---|---|
| ① | 守秘人 | **先做功课**：通读模组，写理解 / 大纲 / 扩展 / 彩蛋 |
| ② | 守秘人 | 出**赛前简报**：不剧透的开场介绍 + 车卡建议 |
| ③ | 玩家 | **报意向**：「我想车个记者，34 岁」 |
| ④ | 大家 | **聊几轮**：互相劝、吐槽、改主意（守秘人也插话） |
| ⑤ | 引擎 | 结算属性：购点校验 + **年龄补正** |
| ⑥ | 玩家 | **定妆**，把卡写出来 |
| ⑦ | 守秘人 | **审卡**：夹带的东西会被逮住 |

### 属性：掷骰或购点

在设置里选 `chargen_method`：
- **roll**（默认）—— 引擎掷：STR/CON/DEX/APP/POW 是 3d6×5，
  SIZ/INT/EDU 是 (2d6+6)×5，**幸运永远是 3d6×5 单独掷**
- **pointbuy** —— 八项属性自己分，默认总预算 **480 点**，每项 40–90，
  幸运仍然单独掷。不合规的方案会被抓出来并自动拉回预算内

### 年龄补正（规则书写着的那张表）

玩家在报意向时写下年龄，引擎照规则书算：

| 年龄 | 效果 |
|---|---|
| 15–19 | STR 与 SIZ 合计 −5；EDU −5 |
| 20–39 | 1 次 EDU 增强检定 |
| 40–49 | 2 次 EDU 检定；STR/CON/DEX 合计 −5；APP −5 |
| 50–59 | 3 次；STR/CON/DEX −10；APP −10 |
| 60–69 | 4 次；−20 / APP −15 |
| 70–79 | 4 次；−40 / APP −20 |
| 80–89 | 4 次；−80 / APP −25 |

EDU 增强检定 = 掷 d100 > 当前 EDU 就 +1d10。上了年纪学识更好、身子更差。

### 审卡：最好笑的那一段

车卡完成后守秘人会扫一遍所有人的卡。**总有人想夹带点不该有的东西**——
在不该有枪的年代带枪、给学者配把电锯。守秘人挑该问的问：

> 「1925 年的阿卡姆，你一个民俗学者揣着把冲锋枪？你怎么带进镇的？」

然后玩家申辩（编来历、讨价还价、"那我换个小点的"），守秘人裁决。
**裁决说「拿掉」，引擎就真的从角色卡上把东西删掉。**

守秘人判断的依据是模组的 `era` 字段（时代背景），
写在 `module_info.yaml` 里。

## 每人一个文件夹

```
data\players\<网名>\
    player.yaml            跨周目玩家记忆（梗、口头禅、对同桌人的看法、生涯）
    memory\<会话id>.yaml    那一局里他操控的角色的记忆树
    sheets\<角色名>.xlsx    用你的 COC7 空白卡填出来的 Excel 角色卡
    sheets\<角色名>.yaml    同一张卡的结构化版本
```

角色卡用的是你的 **COC7空白卡CY22.4 Plus.xlsx**（模板在 `data\templates\`）。

这张卡是公式驱动的，所以填法是**把点数拆回它自己的列**：
属性写进 `人物卡!U3/AA3/AG3/U5/AA5/AG5/U7/AA7/AG7`，
技能按「初始 / 成长 / 职业 / 兴趣」四段分别填，成功率那一列是它自己的求和公式。
这样打开卡的人能一眼看见这 70 点里哪些是职业给的、哪些是兴趣加的。
生命/理智/魔法/MOV/伤害加值全是派生公式，不用我们算。

> openpyxl 不计算公式。填完之后用 Excel / WPS 打开，派生值会自己算出来。

界面右栏「角色卡」和「🧠 玩家档案」里都有 **📂 打开文件夹** 按钮。

## 骰子：AI 自己决定什么时候掷，但碰不到随机源

- 随机数来自**操作系统熵池**（`secrets.SystemRandom`），不是可推导的伪随机
- 模型只能在 `<roll>` 通道里**申请**掷骰，永远拿不到也改不了出目
- 每次掷骰都有审计记录：序号、轮次、发起人、表达式、**每一颗骰子的原始点数**
- 界面上「🎲 骰子」标签页就是这份记录

**骰子不服务于剧情，它只服务于这桌上的人。**

### 明骰与暗骰

| 发起者 | 通道 | 谁看得到 |
|---|---|---|
| 玩家 | `<roll>` / 检定申请 | **全桌**（其他人下一轮看到）+ KP |
| 守秘人 | `<roll>` | **暗骰** —— 只有 KP 和"你" |
| 守秘人 | `<state> openroll` | 明骰，全桌 |

暗骰的出目**不会**进入任何玩家的上下文；玩家只看到它造成的结果。
提示词里对守秘人写得很直白：暗骰不是让你偷偷改结果的借口，
恰恰相反——正因为没人看得见，你更需要老实照着数字说。

## 记忆：先想起名字，再顺着名字捞细节

每个 AI 座位有一棵**认知树**，记录"我现在怎么想"：

```
✓ 门户 —— 大门是从外面用铁链锁的
? 封门者 —— 有人故意把出入口封死了
    属于「是谁锁的门」；关联「里斯」（他就是锁门的人）
… 霍尔本的下落 —— 他去哪了
```

**平时的提示词里只有索引**——名词 + 一句话 + 名词之间的关系。
想要某个东西的**全部细节**（依据、来源、完整原文），
AI 得自己喊一声 `<recall>封门者</recall>`，引擎才把细节捞给它，
然后它带着细节重新把这一轮说一遍。

这是照真实记忆的样子做的：你想起一件事，先冒出来的是几个名字和它们
模模糊糊的联系，细节要顺着名字再去捞。顺带也省 token——24 个节点时索引比全树省一半。

记忆分两层存：
- **角色记忆**随模组结束而死 → `players\<网名>\memory\<会话id>.yaml`
- **玩家记忆**跨模组存活 → `players\<网名>\player.yaml`

## 模组：KP 先做功课，散场才解禁

把剧本丢进 `data\modules\`（文件夹或单个 `.md`/`.txt`/`.pdf` 都行）。

### 开局前：守秘人的功课

守秘人通读模组后，写下**四样东西**：

- **`<spine>` 大纲** —— 把模组的场景 id 原样抄一遍。
  引擎**逐条比对**，对不上就打回重写；再对不上就强制以模组原文为准。
  所以「不能偏离大纲」是可校验的，不是口头保证。
- **`<understanding>` 理解** —— 这故事真正在讲什么、哪几个节点绕不过去
- **`<expansion>` 扩展** —— 只能加不能改，每条以 `[加]` 开头并写明挂在哪一幕
- **`<eggs>` 彩蛋** —— 独属于**这一桌**的东西。引擎会把名册上每个人的
  跨周目记忆（口头禅、习惯、上一局演的是谁）摊给守秘人看，它才知道该埋什么

### 防剧透是两层的

让 KP「写一份不剧透的介绍」光靠一句「不要剧透」是挡不住的，所以：

- **事前**：从模组真相里自动抽出**秘密词表**——那些在真相里反复出现、
  却从没在公开材料里出现过的专有名词——把这张表直接塞进提示词：
  「这些词一个都不许出现」。给出具体清单比抽象禁令有效得多。
- **事后**：用同一张表查它实际写出来的简报，命中就带着命中词重写；
  再命中就退回模组作者写的公开简介。**宁可简报平淡，不能剧透。**

### 结局之后：解禁 + 茶话会

跑完之后模组对全桌开放（原文、handout、幕后真相全部贴出来），
然后开一场**散场茶话会**：玩家说当时以为会怎样、哪个细节回头想起来后背发凉，
守秘人揭晓它埋的彩蛋、承认哪段是现编的。

**解禁只发生在这一刻。** 在此之前，模组原文和幕后真相从来不会进入
任何玩家的上下文——不是靠提示词约束，是代码路径上就拿不到。

## 玩家不可能联网查剧透

这条是结构性的，不是靠请求：

- 引擎**没有任何检索、浏览器或联网工具**——AI 能用的工具只有掷骰（`<roll>`）
  和联想召回（`<recall>`），两个都是纯本地的
- 整个引擎里唯一会联网的地方是 LLM 客户端（`llm.py`），
  自检脚本会扫描源码确认这一点
- 提示词里也写明：你没有联网能力，也不许去查这个模组的任何资料

## 桌边：玩家层和角色层分声部

真实玩家同时活在两个声部。这个引擎把两者显式分开：

| 声部 | 形式 | 内容 |
|---|---|---|
| 角色层 | 不带括号 | 第一人称、现在时、**只写尝试不写结果** |
| 玩家层 | （括号） | 知道规则、知道数值、会算概率、会商量、会吐槽、会脱线 |

分寸就在这个落差里：**沉浸在角色的动机与选择，但不沉浸在文风。**
最典型的活人标志是玩家会说「我侦查才25，别指望我」——
角色不可能知道自己的技能是25，玩家知道。

配套机制：
- **知识边界**：每轮列出「桌上你知道、但你角色并不知道的事」
- **桌边插话轮**：回合之间插一轮纯对话，还原
  「你赶紧过来啊」/「我角色不知道啊」的真实来回

## 换庄：今天你当 KP，明天他当 KP

这桌上的人是**固定的**，但**位置可以换**。

- **记忆跟着人走，不跟着位置走**：半糖这次当 KP、下次当调查员，她的梗都还在
- **API Key 也跟人走**：换位置不会把谁配好的 Key 弄丢
- 内置名册 7 个人（6 个默认当玩家、三男三女；1 个默认当守秘人）。
  名字和性格都能改——**建议直接改成你和朋友的名字**，桌边感会强很多

---

## 关闭界面会不会丢记录

**不会。**

- 每一条叙述、行动、桌边话、骰子在产生时就 append 到
  `data\runtime\sessions\<会话id>\transcript.jsonl`
- 每轮结束写一次 `session.json` 和所有座位的记忆卡
- 关窗时还会再存一次
- **重开界面会自动接上上一局**

## 省 token 的几处设计

| 层 | 内容 | 什么时候注入 |
|---|---|---|
| 常驻 | 判定要点（约 250 字） | 每轮，但极小 |
| 术语 | 39 条一句话定义 | **只在那个词出现时**，整局每词只解释一次 |
| 分节 | 战斗 / 理智 / 恢复 / 车卡预算 | 需要时 |
| 记忆 | 索引（名词 + 一句话 + 关系） | 每轮；细节要 `<recall>` 才给 |
| 全文 | 规则书 PDF 抽取的 82 万字 | 只在你主动检索时查 |

另外：守秘人的模组情报放在 **system 提示**里（能命中服务端前缀缓存），
它的 `<secret>` 每轮完整重写所以历史里只留最近一条。

「成本」标签页实时显示每个座位的 token 用量与费用估算。
真正的大头是**逐字历史**，所以「保留历史轮数」是最有效的省钱旋钮。

## 自检

```powershell
# 引擎端到端自检（零成本，含骰子均匀性检验、剧透检查、暗骰不泄漏、审卡）
.venv\Scripts\python.exe tools\selftest_offline.py 4

# 界面真机链路（真开窗口，从 JS 调 Python，读回真实 DOM）
.venv\Scripts\python.exe tools\smoke_ui.py

# 打包 + 验证打包后的 exe 本身能启动
.venv\Scripts\python.exe tools\build_exe.py
.venv\Scripts\python.exe tools\smoke_exe.py
```

其它脚本：`extract_rules.py`（规则书 PDF 抽全文）、
`build_glossary.py`（挖术语候选）、`probe_sheet.py`（探查角色卡结构）。

## 已知限制

- 尚未做战斗网格与先攻可视化；战斗按 DEX 顺序在日志里叙述。
- 分头行动时不做视野隔离，公开叙述所有人都看得到。
- 剧透哨兵是**词面匹配**，换种说法（把「叹息之像」写成「那尊小雕像」）就抓不到。
  它是兜底，不是保证。
- 规则书全文检索是关键词匹配，不是向量检索。
- **没接原生 function calling**：骰子与回忆用的是文本协议，
  好处是任何 OpenAI 兼容端点都能用，坏处是守秘人自己掷的骰子要下一轮才拿到结果。
- 扫描版 PDF 模组读不出文字（需要先自己转成文本）。
- 离线模拟后端只是占位实现，用来验证流程，不会真的写出好剧情。
